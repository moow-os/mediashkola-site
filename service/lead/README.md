# Приёмник заявок «МЕДИАШКОЛА»

Форма записи на сайте отправляет заявку сюда, отсюда она уходит в телеграм-бот школы
(и, если подключён, в таблицу заявок). Родитель ничего не пересылает руками.

Требование клиента, 16.08.2026, голосовое 22:08:
> «Человек всё заполнил, нажал отправить заявку — и должна упасть заявка в телеграм-бот.»

Адресов **два**, оба обязательны (решение 16.08): телеграм-бот — чтобы увидеть сразу,
и таблица «ЗАЯВКИ ЛАГЕРЬ 2026» — чтобы заявка легла рядом с лагерными, как просила Катя
(«всё в тот же лист, где лагерь, я все различаю!»). Воркер пишет в оба параллельно и судит
о каждом отдельно: если бот принял, а таблица нет — родителю всё равно «отправлено», а в бот
уходит второе сообщение «занесите строку руками» с причиной.

## Почему воркер, а не прямой вызов Telegram из браузера

Токен бота нельзя класть в статический JS: сайт открыт, токен утечёт в первый же день.
Воркер держит токен секретом на стороне Cloudflare, а браузер видит только свой же адрес.

Домен `mediashkola.pro` в Cloudflare стоит **DNS-only** (серое облако): записи ведут прямо на
GitHub Pages, трафик через Cloudflare не идёт. Поэтому маршрут `mediashkola.pro/api/*` работать
не будет — воркер живёт на `workers.dev` и вызывается кросс-доменно, CORS в коде разрешает
только адреса сайта.

## Что нужно один раз

1. **Бот.** В `@BotFather`: `/newbot` → имя и username → он выдаёт токен вида `1234:AA...`.
2. **Кому падают заявки.** Каждый получатель (Катя, менеджер) один раз пишет боту `/start` —
   без этого Telegram не даёт боту писать первым. Затем:
   ```bash
   curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | python3 -m json.tool | grep -A3 '"chat"'
   ```
   `id` из ответа — это `chat_id`. Несколько получателей перечисляются через запятую.
3. **Деплой.**
   ```bash
   cd service/lead
   wrangler login
   wrangler secret put TG_BOT_TOKEN
   wrangler secret put TG_CHAT_IDS
   wrangler deploy
   ```
   Команда напечатает адрес вида `https://msh-lead.<аккаунт>.workers.dev`.
4. **Включить на сайте.** В `assets/site.js` вписать этот адрес в `LEAD_ENDPOINT`, запушить.
   Пока строка пустая, форма работает в старом ручном режиме.

## Проверка после деплоя

```bash
curl -s https://msh-lead.<аккаунт>.workers.dev/health
# {"ok":true,"telegram":true,"sheet":false}

curl -s -X POST https://msh-lead.<аккаунт>.workers.dev/lead \
```

## Таблица заявок — второй адрес

Таблица: **«ЗАЯВКИ ЛАГЕРЬ 2026»**, `1AAQxYUh5ZmdFg0vpa26IFqnD-XOlCPIoOMQ-JkTA8SM`.
Владелец — `dyukovzapas@gmail.com` (Иван), нам она расшарена. Поэтому скрипт сделан
**standalone**: открывает таблицу по ID, внутрь чужого файла не встраивается и структуру
её не меняет.

Живые колонки (сняты с таблицы 16.08): `Name · Email · Phone · referer · formid · sent · requestid`.
Туда же пишет тильдовская интеграция лагеря, поэтому:

- пишем **по именам колонок**, а не по номерам — переставят порядок, ничего не сломается;
- телефон приводим к лагерному виду `+7 (918) 634-29-54`;
- `referer` = `https://mediashkola.pro/` — по нему школьные заявки отличаются от лагерных
  (`https://medialager.ru/...`) с одного взгляда, как Катя и сказала;
- курс и мессенджер девать некуда, поэтому они уезжают в `formid`:
  `сайт-МШ · МЕДИА · Телеграм`. **Если в таблицу добавят колонки `Курс` и `Мессенджер`**,
  скрипт заполнит их сам, а `formid` станет просто `сайт-МШ` — менять код не нужно;
- запись берёт `LockService`, чтобы не столкнуться с тильдовской строкой.

### 🔴 Блокер: у нас НЕТ права записи в эту таблицу

Проверено 17.08.2026 через Drive API (`permissions.list`), а не со слов:

```json
{"permissions":[{"role":"reader","type":"anyone"},
                {"emailAddress":"dyukovzapas@gmail.com","role":"owner","type":"user"}]}
```

То есть у `alvisionn@gmail.com` **нет отдельного доступа**: таблица открыта «всем, у кого есть
ссылка», и только **на чтение**. Скрипт, запущенный от нашего имени, упадёт на `appendRow`.

**Нужен один шаг Ивана Дюкова (владелец):** выдать `alvisionn@gmail.com` роль **Редактор**.
До этого разворачивать Apps Script бессмысленно — деплой пройдёт, запись не пройдёт.

Отдельно к сведению владельца: в таблице лежат имена, телефоны и почты реальных родителей,
а доступ «всем, у кого есть ссылка» — на чтение открыт кому угодно, кто ссылку получил.

Развернуть (после выдачи прав):

1. `script.google.com` → новый проект → вставить `sheet/Code.gs`.
2. Project Settings → Script Properties: `TOKEN` = любая длинная строка (её же положим
   в секрет воркера `SHEET_TOKEN`).
3. Deploy → New deployment → **Web app**, «Execute as: Me», «Who has access: Anyone» →
   скопировать адрес `.../exec`.
4. Проверка: открыть этот адрес в браузере — вернётся список колонок и число строк.
5. В воркер:
   ```bash
   wrangler secret put SHEET_WEBHOOK_URL   # адрес /exec
   wrangler secret put SHEET_TOKEN         # тот же TOKEN
   ```

Пока `SHEET_WEBHOOK_URL` не задан, нога выключена и на доставку в бот не влияет.

Отображение `Code.gs` в строку таблицы прогнано отдельно, вне Google (подменены `SpreadsheetApp`,
`PropertiesService`, `LockService`, `Utilities`): 7 живых колонок → курс и мессенджер в `formid`;
9 колонок с `Курс`/`Мессенджер` → заполняются отдельно; переставленные колонки → строка всё равно
верная; чужой токен и заявка без телефона → отказ, строка не добавлена; `8 909 466-46-44` →
`+7 (909) 466-46-44`.

Чего эти проверки НЕ покрывают: живого бота (токена ещё нет) и живой записи в таблицу
(веб-приложение не развёрнуто). Обе — первым делом после деплоя.

## Чего здесь нет

- Ограничения частоты по IP: защита пока — honeypot и серверная валидация. Если пойдёт спам,
  добавляется KV-счётчик или Turnstile.
- Защиты от двойной отправки: повторное нажатие пришлёт вторую заявку. Кнопка на сайте
  блокируется на время отправки, но это клиентская мера.
