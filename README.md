## Домен, TLS и доступность из России (состояние 17.08.2026)

Домен `mediashkola.pro` — зона Cloudflare (DNS-only), четыре A-записи apex на GitHub Pages
`185.199.108–111.153` + CNAME `www`. Сертификат — Let's Encrypt через GitHub Pages,
`CN=mediashkola.pro`, выпущен 17.08, до 15.11.2026. Приёмник заявок — Cloudflare Worker
`msh-lead` на `api.mediashkola.pro` (Custom Domain, свой сертификат Cloudflare).

**Enforce HTTPS намеренно ВЫКЛЮЧЕН.** Замер с российских узлов (check-host, три узла,
по три прогона, 17.08): TCP до `185.199.x.153:443` устанавливается за 20–40 мс, но
TLS-запрос к `mediashkola.pro` и `*.github.io` на двух московских узлах виснет по таймауту
(15–16 с), а по `http://` те же узлы отдают страницу за 30–90 мс. Контроль: `github.com`
и `api.mediashkola.pro` отвечают 200 со всех узлов. Значит, режется не IP, а TLS по SNI —
волнами, на части сетей. Совпадает с данными OONI о росте отказов к GitHub в РФ с 05.05.2026.

Следствие: при включённом Enforce HTTPS `http://` отдавал 301 на `https://`, который на таких
сетях не открывается вовсе — сайт становился недоступен. С выключенным работают оба протокола:
кто дотягивается до 443, видит валидный сертификат; кто нет — получает страницу по http.

Это компромисс, а не решение. Решение — хостинг, достижимый из России (сайт статический,
переносится копированием). До переноса не включать Enforce HTTPS и не ставить canonical/og:url
с жёстким `https://` — они прибьют пользователя к недостижимому протоколу.
